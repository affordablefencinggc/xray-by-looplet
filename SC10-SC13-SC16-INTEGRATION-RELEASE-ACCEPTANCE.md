# SC-10 / SC-13-16 integration and release acceptance matrix

Status: **preflight only; no future slice is started or complete**

Scope: master `SC-10`, `SC-13`, `SC-14`, `SC-15`, and `SC-16`, reconciled with `XR-INT-CI-01-ledger.md`, `XR-INT-CRM-02-ledger.md`, and `LOOPLET_BRANCH_RELEASE_LEDGER.md`

Sequence: contract intake -> identity/data decision -> transport -> continuous attestation -> signed release
Acceptance IDs: `IR-001`...`IR-112`, contiguous and immutable once implementation begins

This is a plan and evidence contract, not an implementation or completion claim. A row closes only when its build target exists, its named machine proof passes, and its human, sandbox, or clean-machine proof is attached where required. Local source inspection cannot substitute for an external contract, sandbox transaction, remote CI run, signature verification, or clean-machine exercise.

## Hard gates

- **Auth is OFF and database-backed application persistence is OFF now.** Do not add auth routes, auth middleware, tenant columns, migrations, server credential storage, or database imports until `IR-019`, `IR-021`, and `IR-028` are explicitly decided. The durable outbox is a named future requirement, not present authority to enable a shared unauthenticated database.
- If Looplet requires delegated user/org identity, auth and durable storage turn on together behind server-verified identity and tenant isolation. A client-sent user, organisation, target, or entitlement is never authoritative.
- If Looplet does not require delegated identity, the approved design must still provide a safe server credential and ownership model. An auth-off, world-readable/writable outbox is forbidden; use an approved local encrypted queue or another explicitly reviewed ownership boundary.
- Browser navigation, `localStorage`, a staged payload, a mock success, and an opened CRM URL are not handoff. `XR-INT-CRM-02-ledger.md` therefore supplies historical intent only; its former completion labels do not satisfy any row below.
- Local workflow syntax and local builds are not remote CI proof. `XR-INT-CI-01-ledger.md` supplies historical intent only; its former completion labels do not satisfy remote Linux/Windows artifacts, security attestations, or branch gates.
- The active branch remains `feat/v1-production-ready` from baseline `c3ac22cd059d522a44156b6372b1219b0d023dca`. No merge, tag, deployment, or release is authorised by this matrix.
- Never execute the existing unknown `engine/bin` payload, ignored sidecar, old setup executable, or installer. SC-11 must first produce reviewed, reproducible artifacts with checksums and provenance.

## Caterpillar execution rule

1. Do not begin SC-10 implementation until `IR-001`...`IR-018` have owner-supplied inputs; fixture design may be reviewed, but fabricated Looplet schemas do not count.
2. Close the SC-13 decision gate (`IR-019`...`IR-034`) before enabling auth, database persistence, credentials, tenants, or outbox migrations.
3. Implement SC-14 in row order. Transport cannot skip directly from a dry run to “sent”; durable enqueue, idempotency, conflict, attachment, ambiguous-ack, and receipt states are mandatory.
4. SC-15 foundations may be prepared earlier, but no row is complete without current remote evidence at its stated platform and scope.
5. SC-16 promotion starts only from one fully attested candidate. Signing, clean-machine, update, rollback, recovery, and uninstall proofs are one chain; none may be inferred from a build artifact alone.

## Completion condition

This matrix closes only when all 112 rows have both the required implementation diff and the stated executed/human evidence, all external blockers are resolved or an explicitly approved OFF decision removes the conditional feature and every associated claim, and the branch/release ledger records a human-authorised disposition. Until then, SC-10 and SC-13-16 remain future work.
