## Operating contract

1. Fix the definition of done and the release cutoff. Preserve the existing UI positions unless the requested fix requires a change. Resolve the exact missing bottom controls from historical evidence and the user's clarification.
2. One integrator owns shared job schemas, storage boundaries, workspace integration and release identity. Up to three concurrent workers own separate modules. Agents report a stable source checkpoint only after their complete user journey passes, including restart.
3. Maintain an explicit dependency queue: stable project identity and saving → recoverable restore → source/document lifecycle → reviewed pricing → portable handoff → authenticated delivery and connected research.
4. Run focused tests and isolated-profile browser workflows during implementation. Exercise failure states: corrupt input, missing originals, quota/storage denial, stale windows, interrupted writes, restart and incompatible package versions. Capture meaningful screenshots and inspect them.
5. Freeze a complete tested batch before packaging. Updated user allocation: build web/native sequentially on Dans1 at High priority using all 16 logical processors, with memory available to the workload. Use `scripts/dans1-build-worker.ps1` and its dedicated resource policy. Local background build assistance is optional and must be capped to at most 20% aggregate CPU before launching; worker counts alone do not enforce a CPU quota. Copy proven caches into isolated run directories, preserve old snapshots, and verify all source/artifact hashes.
6. Check built web output and native behavior. Prepare recovery before any installed update. Preserve the user's running work; no forced closure or unverified replacement. One final package identifies exactly the verified source snapshot.

Rotate workers through independently testable slices. Do not run multiple writers on shared schema/store files. External build orchestration consumes one worker slot when needed; it does not justify an extra concurrent implementation writer.

## Dependencies that code alone cannot supply

- A selected authentication/shared-storage service, provisioned project memberships and test staff accounts for multi-user workflows.
- Secure provider configuration and an agreed usage cap for real Firecrawl research, plus selected supplier searches to execute. Never include credentials in source snapshots or screenshots.
- Representative approved drawings, supplier sheets and expected results for each specialist workflow under acceptance.
- Appropriate review of discipline-specific calculations, assumptions and jurisdictional requirements. Generic models or fixture calculations are not certification.
- A defined staff recipient and explicit instruction before sending any message. A downloaded package is not proof of receipt.
