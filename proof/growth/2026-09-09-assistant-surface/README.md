### Model mode — the render-visibility fix and the full green run

The first full run exposed a real gap rather than a test artifact: the viewer set `data-source-sha256` on the canvas from `model.source.sha256`, which for a designed model is the *designed* digest. `captureCanvasImage` copies that attribute into the render receipt (`appTools.ts:156`), and the Render pane only shows a render when `latestRenderMatchesProject(latest, jobId, source?.sha256)` holds (`RenderStudio.tsx:22`, `renderTool.ts:118-119`). A designed model has no source plan, so the digest never matched and the pane showed "OTHER PROJECT" — **the render succeeded but was invisible**.

Fix (`SourceBuildingViewer.tsx:108-112`, fenced `[SC-21 designed model]`): a designed scene reports no source identity at all — `delete renderer.domElement.dataset.sourceSha256` — which is both truthful (there is no source drawing) and satisfies the matcher's existing `latest.sourceSha256 === null` branch. The camera snapshot (`modelViewSnapshot.ts`) was deliberately left alone: `recordModelView` legitimately requires a real source identity, and widening that type would weaken a genuine contract for an unrelated reason.

Re-run `modelmode-3`: **exit 0, all four legs.** Designed scene mounted (23 objects, `sourceSha256` now empty, status `designed`); Magic Pencil drew it for 844 frames naming `{"id":"designed","title":"Designed model"}`; the render returned 620 × 436 and **appeared on the Render pane** at 1184 × 864 with alt text "AI-generated visualisation of the captured 3D view" and the caption "captured source-building 620×436 frame 844 · sheet 1 · no source link · session memory only"; `hide_designed_model` returned the viewer to its catalogued source reconstructions. Screenshots `model-01-designed-in-viewer.png`, `model-02-magic-pencil.png`, `model-03-real-life-view.png`, `model-04-back-to-source.png`.
