## CSV — proven bytes, blocked file capture

**BLOCKED:** the runner's `download` opcode returns `{"success":false,"data":null,"error":"Download was canceled"}` and writes no file. Minimal reproduction, with no QS code involved: a synthetic `<a download>` carrying a `blob:` href, on a bare page, clicked through the same opcode, is also canceled. Both native Windows backslash and forward-slash destination paths fail identically, and the browser reports no page errors. This is a harness/browser blob-download limitation, not a product defect and not a path-escaping fault. Recorded as blocked rather than retried until it appeared to pass.

CSV contents were instead proven by capturing the exact `Blob` the product's own download handler creates. `QuantityReportView.tsx:34` builds the file as `URL.createObjectURL(new Blob(['﻿', quantityReportCsv(shown)]))`; the scenario wraps `createObjectURL`, clicks the real enabled Download button, and reads the real Blob's text. These are the product's shipped bytes minus the separate BOM element, not a reimplementation.
