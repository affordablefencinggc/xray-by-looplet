### Scope

A new "Supplier product research" section at the end of the Cost pane's price book panel lets a user start one bounded Firecrawl v2 web search (query, country, optional single supplier domain, 1–5 links) and see either real candidate links with query/country/timestamp/credit information or an honest typed failure. The provider key lives only in server `process.env`; the route is same-origin, JSON-only, body-capped and returns `{ result }` or `{ failure }`; the server adapter fixes the upstream URL, bounds time (35 s) and response size (1 MiB), serialises to one in-flight search, never retries and never echoes the key or provider bodies. Search collects evidence links only: nothing is stored and no rate, worksheet or project cost changes.

### Exact diff summary

Shared Zod contract `xray.pricing-research/v1` (request: query 1–200 trimmed, ISO alpha-2 country default AU, location ≤120, include XOR exclude domains ≤3, limit 1–5, projectId, requestId, `.strict()`; candidate: public-HTTPS-validated URL, title ≤300, description ≤1000; result with `creditsUsed: number | null`, `nominalCreditEstimate`, optional `providerJobId`/`warning`; failure enum incl. `not-configured | disabled | unauthorized | payment-required | rate-limited | timeout | cancelled | invalid-response | too-large | upstream-error | busy` plus `invalid-request` for route-level rejections). `estimateSearchCredits(limit) = 2 × ceil(limit/10)`. Server adapter `searchSupplierProducts` POSTs `{ query, sources: ["web"], limit, country, location?, includeDomains?|excludeDomains?, timeout: 30000 }` to `https://api.firecrawl.dev/v2/search` with a Bearer header, maps HTTP/abort/timeout/size/shape failures to typed `PricingResearchError`, drops non-public URLs (counted in `warning`), caps candidates at `limit`. Route: GET status, POST with same-origin check, JSON content type, 64 KiB cap, status codes 200/400/403/409/413/415/502/503, always `no-store`. Panel: GET status on mount only; search from the button only; Cancel via AbortController; failure renders code + HTTP status + message + explicit "Try again"; result renders summary, credit lines and `rel="noopener noreferrer" target="_blank"` links; unavailable state when the status probe fails (native builds).
