# Movement scenario tooling

`navigation-movement-scenarios.mjs` exports `navigationMovementSegment(options)`, `SOURCE_CANVAS` and `ARCHITECT_CANVAS`. It generates ordinary string-array agent-browser opcodes for the existing `scripts/fast-cdp-test.mjs` runner. No browser driver, arbitrary sleeps or app-source changes are introduced.

The original four example JSON files contained 30 commands. The current exported segment contains 32 commands: it additionally records the settled frame and waits for the next actual rendered frame before inspecting heading. This resolves an observed test-readiness race where arrival became idle before the following tick refreshed yaw/speed. Existing executed scenarios are preserved; regenerate into uniquely named files through the export. Segments assume the corresponding viewer is already visible and the chosen mode has been entered through the UI. Root owns startup, useful-view screenshots and input-denial injection.

The segment reads `cameraPosition`, `navigationYaw` (or `navYaw` alias), `navigationPitch` and `navigationSpeed`. At a near-zero/straight-axis yaw, look/drag events turn the actual view before movement. Each W/S/A/D case dispatches a bubbling KeyboardEvent, waits for at least 0.12 metres of actual camera displacement, releases the key, waits for velocity to settle, then checks camera-relative signed dot products. Walk height must remain fixed; optional `expectedEyeHeight` also verifies the selected floor plus eye height. Strafe must not change altitude. Samples and results are returned to the executed log.

A five-second failure deadline is a key-release safety guard, not a sleep or success predicate. It releases held keys and exits navigation if a stalled batch would otherwise leave movement active. Successful flow explicitly releases every key, captures screenshots and presses Escape by KeyboardEvent before waiting for orbit/unlocked state. On external failure, a separate cleanup eval can call `Object.values(window.__navigationMovementProof ?? {}).forEach(state => state.cleanup())`.

Combine the returned segment after an existing startup sequence. **Every execution must use a unique `tag` and `screenshotPrefix`, including platform, floor and attempt identity.** Do not rerun the generated examples against the same screenshot paths: agent-browser screenshot output replaces an existing image. `expectedEyeHeight` is optional and walk-only. Generated default names under `screenshots/growth/2026-09-08-navigation/` are illustrative and must be replaced for repeated runs.

Evidence correction: an upper-floor run reused the original `source-walk` default prefix and replaced the ground-floor movement PNGs. The ground-floor interior screenshot and both executed 30-command movement logs remain separately available; the original ground movement screenshots must not be claimed as retained. Subsequent platform/floor runs use unique prefixes.

Preparation validation parsed all four JSON scenarios and compiled their eval/wait JavaScript expressions without executing them. This checks syntax and opcode shape only. No live session was run and no movement acceptance is claimed by generation. Root's Architect QA agent owns its subsequent `architect-*` execution artifacts; do not regenerate over those files after execution.
